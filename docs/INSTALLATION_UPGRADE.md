# 安装、升级与依赖复用

安装入口仍为 `setup.ps1`。现在 PowerShell 会在任何下载或系统组件安装前校验发布清单，
Python 安装入口也会独立检查清单、wheel、源码对应关系与模型下载计划。
可先运行 `./setup.ps1 -VerifyOnly`，该命令只校验文件，不接受许可、不下载也不安装。

## 升级已有部署

1. 更新仓库后重新运行 `setup.ps1`。原有 `.local` 状态保留时，默认沿用工作区和模型选择；
   显式传入 `-Workspace` 或 `-Models` 时使用新值。
2. 安装器检查既有依赖环境的 Python 3.11、64 位 ABI、所有固定版本与源码归档 SHA256。
   兼容时直接复用，不重装 Torch、Paddle 或其他依赖；不兼容时建立独立的新依赖环境。
3. 新 wheel 安装到独立的小环境，通过 `.pth` 引用依赖。重复安装同一有效 wheel 会跳过安装。
   使用 `-RuntimeDirectory` 指定的旧目录不会被覆盖；不匹配时在旁边创建带后缀的新目录。
4. 包文件检查、pip check 和真实 GPU doctor 全部通过后，才原子更新 `.local/runtime-selection.json`。
   失败记录在 `.local/last-setup-attempt.json` 和独立日志中，不激活未验证环境。
5. 重启 MCP 会话。建议将新生成的 `.local/mcp-client.json` 重新导入客户端一次：
   新配置使用稳定的基础 Python，由启动器读取当前已验证运行时，后续不再固定每个 wheel 的路径。

旧 `.local` 配置中登记的 `--runtime-python` 路径会被记录为迁移别名，启动器可将其导向新环境。
但旧配置的启动命令本身仍可能指向旧 Python，因此在重新导入新配置前，必须保留旧环境。
未登记的显式 `--runtime-python` 仍作为手动覆盖处理，并接受原有 wheel 字节校验。

## 复用其他安装目录的依赖

可通过 `-DependencyRuntime <已有环境目录>` 显式指定依赖来源。
只有完整满足固定依赖契约的环境才能复用，校验不符会报错且不修改指定环境。
当前部署记录缺失时，不会擅自遍历所有 Python 环境或猜测可复用目录。

依赖环境是共享运行基础，不能单独删除。安装器不自动清理旧环境、知识库或教材文件。
如果重复安装曾失败，旧目录保留用于诊断，新尝试使用另一个目录。

## 回退与限制

更新仓库但尚未安装成功时，旧运行时不能冒充新 wheel；启动器会提示完成安装。
失败会保留旧激活记录、旧工具与依赖，但使用旧版本还需要恢复与其匹配的整个旧发布包。
每次安装日志中的 `previous-activation.json` 保存切换前记录。

共享依赖复用以固定版本和源码归档身份为依据；之后仍执行 pip check、包字节核验与 GPU doctor。
这不是转换准确率或速度验收。GitHub 的安装测试使用原创小 wheel 和模拟 doctor 验证状态切换，
不会将没有 GPU 的 CI 标为完整 GPU 安装通过。

2026-09-22 在独立本地测试目录完成了真实升级及再次执行 setup：复用既有公开版环境的
107 个固定版本依赖和 1 个源码归档，两次 GPU doctor 均为 `READY_FULL`。
首次只安装新工具 wheel，第二次工具与依赖均未执行 pip 安装。
旧运行时路径的迁移和不指定运行时的新启动方式，均通过官方 SDK 的 auto/legacy 两类会话。
全新下载全部依赖的分支保留原有版本与源，并有流程测试，本轮未重新下载整套 CUDA/PyTorch。
