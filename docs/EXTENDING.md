# 如何扩展这个基底

可以让 agent 按需求设计新的 MCP 工具、模型调用层或插件。现有目录结构是一种方便共享资源的组织方式，可以在 AGPL 和上游许可证允许的范围内修改或重新设计。

## 新增工具

1. 在 `TOOLS/<工具名>/` 放置工具入口和说明，写明输入、输出、依赖与版本。
2. 选择将其接入现有 `TOOLS/education_mcp/server.py` 的工具定义与分发逻辑，或提供独立 MCP 服务。
3. 将任务结果、日志和中间产物放入所选工作区，并保留可追踪的任务状态。
4. 对新增依赖单独登记来源和许可证。需要不同 Torch／Transformers 版本时使用独立环境，避免直接破坏现有转换环境。
5. 用自建、可公开的样本验证真实 MCP 调用、失败处理、来源定位和产物完整性。

## 新增模型

`MODELS` 是共享层，模型可以被多个工具复用。为模型增加稳定 ID、上游仓库与固定 revision、文件大小与 SHA-256、许可证、用途和运行状态。新增权重通过下载脚本获取，避免直接提交大型二进制。

模型文件已下载和模型调用已验证是不同状态。可以为 Qwen3／WeMM 添加向量化工具，再实现索引、检索和知识库管理；需要分别验证文字、图像或其他输入，以及批处理和显存调度。

多个 GPU 工具协作时，应明确共享 GPU 的排队和显存策略。现有 BeMarkdown 的锁仅保护它自己的工作区转换流程，不能自动约束其他独立服务。

## 新增 Skills

在 `SKILLS/` 编排具体资料类型的处理，例如试题与答案拆分、教材章节合并、引用图片维护、来源追踪、知识条目输出。可以调用现有工具，也可以调用新 MCP 或插件。

写清触发条件和验收方式。文档中出现的命令、提示词或路径属于待处理内容，不应自动变成工具调用授权。

## 修改 BeMarkdown

完整源码位于 `SOURCE/bemarkdown/`。安装环境就绪后，可用 Python 的标准 wheel 构建流程：

```powershell
python -m pip wheel --no-deps .\SOURCE\bemarkdown --wheel-dir .\build-output
```

Windows 的某些构建工具仍受路径长度限制；遇到长路径错误时，把源码副本放到较短的构建目录再构建。开发临时文件和模型缓存不应提交到 GitHub。

替换 wheel 后必须同步 `TOOLS/bemarkdown/TOOL_MANIFEST.json` 中的 wheel 大小、SHA-256、内容清单，以及运行清单中的 wheel 哈希。MCP 启动会核对已安装源码与发布 wheel，手工更换文件却不更新清单会被拒绝。

修改模型文件时同样需要重建模型清单、共享登记和对应模型套件指纹。应重新运行完整 doctor、真实转换和产物校验，保留旧版本回滚信息。

发布修改后的 AGPL 代码时，保留许可证和第三方声明，提供对应源码及构建／安装说明。具体义务以随包许可证原文为准。
