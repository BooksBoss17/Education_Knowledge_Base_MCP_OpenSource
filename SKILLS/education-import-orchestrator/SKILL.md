# 教育资料导入调度

接收用户指定的资料、意图与知识库。专用导入工作区按其附件约定启动；普通会话仅附文件且意图不明时先确认。只要求查看、转录或测试时，按用户指定的阶段结束。

## 任务登记与统一收尾

主会话在业务工作区断点中先保存一个新生成的 32 位小写十六进制 UUID 作为 task_run_id。第一步调用 runtime_jobs(action="begin", task_run_id=...)，保存返回的 capture_id。用 runtime_monitor(status, capture_id) 确认已有首个样本，再启动转换。重连时用同一 ID 查询 inspect，继续开放的任务；明确暂停后用 resume 恢复同一任务并记录新的采样段。

外部审查与本地整理脚本在同一采集周期内执行。派工单传递 capture_id、业务根和 task_run_id，主会话记录各阶段起止时间，核对 inspect 返回的关联作业及最终采样覆盖。

主会话自由选择当前可用的 API 和并行子任务。把同一 task_run_id 放进派工单，主会话与子 agent 的每次业务工具调用都携带它。管理器据此登记在途调用和受管作业。原生子 agent 的创建、等待、回收由宿主执行；完成或暂停前，先收回在途派工并保存结果。

任务结束时调用 runtime_jobs(action="end", task_run_id=..., outcome="complete")；暂停用 pause，用户取消用 cancel。管理器封住新提交，等待同步读写退出，正常或暂停时排空已提交的作业；取消时撤销该任务独占的受管作业。状态 CLOSING 表示管理器正在收尾，可用 inspect 查询，客户端断线后仍继续。最后一个持有者释放本批监控。记录最终状态、作业退出凭据和监控回执。只有 COMPLETED、PAUSED 或 CANCELLED 才能报告对应的任务终态；未确认退出的工作保留在收尾中。

## 批量课标与教研 PDF

主会话启动任务、确认首个资源样本并完成连接的视觉验证后，调用 `import_batch(begin)`。把全部 PDF 的绝对路径和原件 SHA-256 一次传入 sources，batch_id 使用已保存的 task_run_id。同一任务中已经提交过的来源附上原 job_id，让批次核实后接管。重连先用 status 或 list 查询；响应丢失时使用同一 ID 和同一清单重试。批量转换由管理器逐份派发，客户端可以断开。可用工具列表缺少 import_batch 的安装版，仅支持原有会话内调度；需要无人值守测试时使用带该工具的版本。

用 events(after=上次确认的序号) 接收持久事件。宿主有后台事件消费能力时，收到 WAITING_AGENT 后唤起视觉审查者；其他宿主通过本机桌面提示或用户打开会话后重新领取。Windows 通知显示取决于系统通知设置，events 和 status 在重新连接后仍可读取。CPU/GPU 及采集连续性通过 status.monitor 和当前 capture_id 核实；遇到 MONITOR_INTERRUPTED 保留前后两段并报告缺口。

借助 claim 和 reviewed 持久交接每批最多 4 页；主会话给每个审查者保存唯一 claim_id。超过 15 分钟需使用原 claim_id 调用 claim 续约。已完成页的核查说明用 pages 分页读取，详细更正和原图证据沿用业务工作区记录。一个文档必须逐页提交已核说明后才能确认发布。把这些说明原样用于整理计划 pages。发布脚本返回指纹后调用 published，管理器检查成品、来源、审查说明与原件备份。FAILED 文档可继续调查；用户明确同意某份跳过时才使用 skip 并写入原因。仅在逐份对账通过后结束整批，暂停或取消沿用 runtime_jobs(end)。

## 选择线路

逐项判断用户指定的用途、资料内容和来源；教材和课程标准都可能是 PDF。同批可以有多种类型，每项单独记录选用的线路。目前已接入：

| 资料类型 | 主会话的工具与发布步骤 | 子 agent 的工作规范 |
| --- | --- | --- |
| PDF 课程标准、评价体系、教学与考试研究资料 | BeMarkdown 转录，按原件校对与预览，使用业务 Skill 随附整理程序发布 | [课标与教学研究资料导入](../curriculum-research-import/SKILL.md) |
| 试卷、作业、讲义拆题入库 | BeMarkdown 转录各原件，exercise_import 暂存、对账和发布 | [题目导入](../exercise-import/SKILL.md) |
| 独立知识手册、考点总结、公式表 | BeMarkdown 转录，checklist_import 暂存、逐段审查和发布 | [知识清单导入](../knowledge-checklist-import/SKILL.md) |
| 本地教学视频或 B 站教学视频 | 标题或作者先检索，BV 下载或接收本地文件；speech_transcribe 转写并按视频归档 | [教学视频导入](../instructional-video-import/SKILL.md) |
| 教材 | 通过 textbook_import 完成审查、审批与发布 | [教材导入](../textbook-import/SKILL.md) |

遇到尚未接入的类型，记录该项所缺的线路，继续处理同批已就绪的资料。新增类型时在表中登记其业务入口。业务入口说明支持的输入、可调用 API 或 MCP 工具、阶段依赖、可恢复作业标识、审查单位、成品位置和发布条件。

导入含系统知识梳理的讲义时，把同一 BeMarkdown job_id 交给题目和知识清单两条支线。分别保存 exercise_import 与 checklist_import 的 import_id、revision 和回执。知识审查可提前推进，发布时先对账讲义全文、原件和题库，再发布知识清单。两条支线均收到回执后计入完成。已有归档讲义补提清单时，直接以已发布的原件 SHA-256 接入知识支线。库存中含 ZIP 时按知识清单 Skill 的盘点步骤去重，再派发唯一原件。

## 调度 API 与子 agent

1. 在业务工作区的任务暂存位置按输入保存来源身份、目标、线路、阶段、作业 ID、最新版本和回执。恢复时先查询真实状态，复用已成功的输出，接续仍在运行的作业。
2. 只提交上游结果已就绪的阶段。按运行管理器提供的队列容量、设备余量和阶段峰值安排本地 API；资源信息不足时沿用已验证的执行顺序。将资源准入和模型装卸交给运行管理器。跨资料可重叠执行转换与审查。状态未知时先核对，已确认可恢复的失败按线路有界重试。
3. 由主会话通过宿主的原生功能派发子 agent。整批跨所有资料类型共用 **3 个并行子 agent 名额**。模型 API 作业单独计资源。当名额已满，记录下一件可派任务；收到结果并释放名额后补派。每份成品同一时刻只有一名写入者。
4. 派工单随附该类型的业务 Skill 和规范，写明连接与工作区、来源和版本、处理范围、可执行操作及返回位置。宿主无法按名加载时传可读路径或规范正文。子 agent 交回实际处理范围、证据、版本和未决项。若宿主缺少该线路所需工具或独立上下文，记录受阻项及断点。
5. 汇总时对照程序中的实际决议、待审数量及最终预览。未决的必要内容留在暂存区；满足该线路的覆盖、版本与发布条件后由主会话提交，并保存真实回执。按资料列出成品位置、处理范围、阶段耗时和剩余限制。

## 局部受阻时继续调度

单页或单项无法修复时，登记来源、待审编号和阻碍，暂停该项的发布。继续派发同一资料的其余独立范围，再处理其他资料。用已审物理页集合与输入页数对账，同时检查待审队列；队首若全是已记录的受阻项，翻页领取其余事项。每份资料的全部可执行范围都已处理，或有明确影响整份资料的阻碍，才将它计为本轮终态。

发布前逐项核对实际页覆盖和未决页清单。没有初始待审编号的受阻页也要按业务线路登记未决项。出现未核或受阻页时，即使程序队列显示待审为零也保留草稿。
