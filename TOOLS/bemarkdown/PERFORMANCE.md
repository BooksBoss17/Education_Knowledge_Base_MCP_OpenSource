# BeMarkdown 提速功能使用说明

本次新增功能保持原模型、精度、单张推理、2048 token 上限和系统 RAM/VRAM 保护线。具体安装状态与实测结果以交付报告和正式安装收据为准。

## 默认行为

单文件入口保持原识别路线。文件交接新增有界恢复：短暂访问拒绝/共享占用会重试同一个文件操作，完成的推理不会因此重跑；永久失败仍明确返回，并保留日志和临时文件。重试上限为每操作9次/2秒，不能中断已进入的系统调用。

## 小批版面阶段复用

原生受管入口可以重复传入 `--batch-source`，最多32份不同路径的输入。`--layout-batch-size 4` 表示每个窗口最多4张图片共用一个版面模型进程，仍逐张推理；版面模型退出后才处理文字、公式等阶段。每份输入仍有独立结果包。

```powershell
& '<受管Python路径>' '<MCP根>/TOOLS/bemarkdown_optimized/convert.py' `
  --source 'D:/inputs/first.png' --batch-source 'D:/inputs/second.png' `
  --output-root 'D:/outputs/batch-unique' --mcp-root '<MCP根>' `
  --layout-batch-size 4 --json
```

默认窗口为1。复用目前只作用于独立图片的版面阶段，PDF/DOCX走既有路径；文字/公式模型尚未实现跨文档阶段合并。完整PDF本来就在同一版面阶段处理多页，不能直接套用此次裁图收益。整个批任务纳入同一个管理器记录、Windows Job、去重和取消流程。新批次使用新的输出根；中断后先查询任务状态，不能再次直接启动相同脚本。

Python API 和开发CLI提供 `layout_batch_size=2..4` / `convert-batch --layout-batch-size 4`。正式用户优先用上述受管入口，以保留跨会话资源监管。

## 异常重复生成早停

受管原生入口增加 `--repetition-guard`，默认关闭。守卫仅针对持续、长时间的自然语言句段周期重复；短重复、数字及公式仍使用原生成预算。它是保守异常检测，并不覆盖一切乱码或中文无空格循环。

触发后保留原始生成前缀、token及事件证据，输出 `REPETITION_ANOMALY`，不得把此前缀当成已完成转录。后续继续现有模型回退/未决审查。守卫开关、参数及源码哈希绑定预测缓存，不会把旧策略预测当作新策略完成结果。

## 计时和复查

批总时间除输入数是吞吐摊销时间，不是每个输入的响应延迟。逐项 `wall_seconds` 为本项版面预计算加内容转换时间，窗口卸载等共同成本只包含在批总时间中。即使下游停止，已做过的预计算也保留阶段状态与耗时。

版面预计算仅在本次调用窗口内使用；消费时核对原文件SHA、派生PDF身份、渲染SHA、像素与尺寸。复用不代表免审；是否需要agent仍由现有审查计划与有效审查凭证判断。
