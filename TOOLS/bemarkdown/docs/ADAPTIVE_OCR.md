# BeMarkdown 自适应三识别器链路

模型分工：PP-OCRv6_medium_rec提供检测行文字证据，OvisOCR2识别完整图块，Xiaomi-OCR-0仅在主输出异常或PP文字证据分歧时复核。PP-DocLayout_plus-L和PP-OCRv6_medium_det仍是公共前端；表格与FormulaNet组件继续独立保留。

PP快速放行默认关闭。模型置信度、两模型一致和多数票不能自证正确。混合公式整块输入，不能通过行图拼接替代二维识别。最终默认采用Ovis；异常主输出可由有效Xiaomi恢复，小范围纯标点差异可按同一字词内容和PP一致证据恢复；实际字词或数学结构分歧留待核，不用物理知识纠错。

旧的PP字符坐标行内数学修补和分式修补默认关闭：Ovis已转录完整混合图块，不能再把基于PP文本跨度的补丁套在不同的Ovis全文上。原生PDF/Word数学提取及独立FormulaNet兜底不受影响，旧修补模块只保留给明确的旧版/实验调用。

比较器保留分数分子/分母边界、上下标、上横线、向量与重音；不做代数等价。旧线性分数归一化不能用于新路由的一致性判断。

Torch在独立子进程运行，与Paddle宿主隔离。运行时按用户安装状态解析，默认位于LOCALAPPDATA/BeMarkdown/runtimes/qwen-ocr-py312-torch214-tf517-v1；允许显式BEMARKDOWN_QWEN_PYTHON覆盖到已验证解释器。共享Paddle运行时不升级，不能引用开发区tmp中的Python或模型。

Qwen单批逐图推理、BF16、贪心解码、2048新token预算、保持长宽比且最多约1M像素。模型按本地注册表固定提交和全载荷SHA深验，不联网下载。模型阶段完成后子进程退出释放GPU；按输入、worker、生成参数、版本和模型指纹绑定缓存。失败、空输出与截断不缓存为成功，不降级到CPU。

预测先冻结再评分。现有286张裁图包括224纯文字、62文字含公式；其来源及AI辅助参考的局限沿用公开评测报告。策略回放、真实冷缓存推理、温预测缓存、原页流程分别记录，不互相冒充；框架分配峰值与设备总显存采样分别报告。

发布遵循冻结RC、暂存验证、事务替换与发布后验证。SVTR/GOT从现役套件与注册表撤出，载荷移入发布回滚备份，历史worker和审阅证据可继续作为明确的旧版本回放工具，不构成现役依赖。其他模型与项目不得清理。
