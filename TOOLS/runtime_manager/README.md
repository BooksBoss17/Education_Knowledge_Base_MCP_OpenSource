# MCP 运行管理与资源预算

状态：候选实现说明；以发布报告中的安装验证结果为准。

## 日常使用

教育 MCP 的 `bemarkdown_convert` 和语义筛图的 `semantic_retention_start` 返回持久任务编号。相同输入、版本和配置的活动请求只启动一次。跨工作区、跨 MCP 客户端的重任务共用用户级队列，同一时刻只运行一个重任务；查询、人工审阅不占这个槽位。

`runtime_jobs` 支持 `list`、`status`、`adopt`、`cancel`。重新连接先查询旧任务；`adopt` 登记当前客户端接管关系，不重新执行模型。取消必须提供任务编号，只终止管理器明确拥有的 Windows Job 及其后代。

BeMarkdown 原生入口 `TOOLS/bemarkdown_optimized/convert.py` 同样进入队列。其 stderr 输出 `managed_job_id`，stdout 保留 JSON 转换结果。关闭前台 CLI 或 MCP 客户端不等于取消任务。保留的可选 legacy-completion 路线仍需显式指定；本轮没有启用它或调用 DeepSeek。

已成功完成的任务保留结果。再次明确提交相同输入允许生成新任务及独立输出。管理器崩溃时，持有的 Job 负责清理模型进程，重启把运行中的记录标为 `INTERRUPTED`，不会自动重跑。确认原任务状态后，可在 `bemarkdown_convert` 使用 `retry_job_id`，在原生 CLI 使用 `--retry-job-id`，或在语义筛图使用该工具的 `retry_job_id`（12 位公共编号）显式重试。

## 自动资源档位

预算在安装目标电脑运行时检测，不将开发机的容量写入发行包。

| 物理内存档位 | 项目私有提交上限初值 |
|---|---:|
| 8–12 GiB | 6 GiB |
| 16 GiB | 8 GiB |
| 24 GiB 及以上 | 12 GiB |

项目私有提交、物理可用内存、系统提交余量分别监测。总提交容量不足时还会下调项目上限；例如无分页且总提交仅 8 GiB 的设备，需保留 3 GiB 提交余量，项目上限会降为 5 GiB。不能把私有提交上限当成物理工作集占用。

本机 32 GiB 档位使用 12 GiB 项目上限，并保留 8 GiB 物理可用、9 GiB 系统提交余量。Windows Job 硬限制扣除控制器预留；持续监测包括控制器和模型后代。保护线不足时，尚未启动的任务/阶段等待；预计需求超过设备能力则返回 `CAPACITY_INSUFFICIENT`。任务默认排队期限 900 秒，阶段默认等待 60 秒；超时清楚记录，不无限等待。

显存按目标卡总量预留桌面和驱动空间。本机检测总量 12282 MiB，预留 2048 MiB，整卡使用上限 10234 MiB。显存采用预计准入、模型分配限制及持续采样停止机制；它不是显卡驱动层的绝对瞬时硬隔离。其他应用新增的显存占用也会影响准入和运行保护。

WeMM 保留原有 bf16 精度及 CPU 权重卸载策略，原 `6gb`/`10gb` 模型放置档位再受设备上限约束。本轮没有改变 OCR 模型、提示词、裁图大小或转录预算来绕过限制。低配机器无法容纳某个固定模型时会明确拒绝，不自动换模型。

WeMM 的准入预估单独登记为 11 GiB 私有提交、8 GiB 物理增量、3 GiB 最低 GPU 增量；GPU/CPU 实际放置仍由既有预算器决定。其权重读取改为只读映射，避免 Windows 为整份可写映射预留提交内存。在 GPU 拷贝同步完成后，仅对当前 worker 做一次工作集回收；私有提交硬限制和系统保护线始终有效，推理期间不循环回收或跳过监控。

## 运行范围与恢复

统一管理覆盖教育 MCP 转换、教育 MCP WeMM 筛图、BeMarkdown 原生 CLI 以及独立 Semantic Retention MCP。`TOOLS/bemarkdown` 继续提供现有依赖启动环境。直接绕过这些入口运行历史 Python 脚本或 `python -m bemarkdown` 的任务没有自动获得登记；不按进程名猜测或批量结束它们。

任务登记默认在 `%LOCALAPPDATA%/BeMarkdown/run-manager`。数据库记录任务与指纹，任务目录保存请求、输出、资源记录和清理结果。日志轮转保持内存及日志大小有界。开发测试可以指定隔离的 `EKB_RUN_MANAGER_HOME`，生产客户端应共用默认目录。

旧版本的已完成结果仍可读取，并标记为 `LEGACY_UNMANAGED`；旧的运行状态不自动转换成新管理器所有权。升级时先排空新管理器队列，再停止管理器、替换已验收包。不得删除数据库来强行消除任务冲突。解释器、登记程序或资源策略发生变化时，管理器拒绝沿用不一致版本，要求排空后更新。

首版仅支持已验证的 Windows、单张未重映射 GPU 0。其他 GPU 映射会明确拒绝，避免监错显卡。模拟低配测试不代表已在那些电脑上实测；发布报告另列真实验证范围。

已验证客户端专有 Job 退出后管理器及任务仍可继续。管理器可能仍属于桌面宿主的外层 Job；系统强杀、退出整个宿主或设备关机不属于“不间断运行”保证。此时依据持久记录恢复为中断状态，禁止盲目重启。12 GiB 是项目策略上限：worker Job 扣除控制器预留后具有硬限制，控制器与进程树合计使用持续采样保护，不宣称所有退出瞬间都达到绝对瞬时聚合上限。
